## 1. 先说明：本目录里存在三种不同“结果来源”

审查时最容易发生的错误是把不同来源的数字混成同一个实验。因此这里强制分开。

### A. 原 Cycle88 历史 strict 实验

这是原研究目录中 `numeric_v2/full_existing_F0_F9 + lgbm_segmented` 的严格跨月结果，是科研历史证据。

### B. 本 `spread24_senior_review` 独立重构包

这是为了师兄审查重新实现的轻量 runner：

- 不依赖原 Cycle88 runner；
- 不依赖原项目绝对路径；
- 使用 `data/frozen_repro`；
- 使用自己的 `config.yaml / src/`；
- 目标是可读、可运行、可审查，而不是逐位复制原实验。

### C. 本包不同时点留下的 standalone run

README 曾记录过一组较早 standalone 运行结果；当前 `outputs/metrics.csv` 又对应另一组已落盘运行。没有完整 provenance 的情况下，两组数字不能自行拼接。

## 5. 这组逐月结果告诉我们什么

### 5.1 Raw 有明显月份依赖

最好月份：

```text
May  ≈ 62.63%
July ≈ 60.75%
```

但其他月份大多在 51%-55%。

因此不能用五月/七月单独代表跨月能力。

### 5.2 July 是典型“Raw 尚可但类别塌缩”

July：

```text
Raw      60.75%
+Recall  84.26%
-Recall  20.44%
Balanced 52.35%
```

模型大量偏向 positive。

这就是为什么老师建议：

- 直接二分类；
- 类别不平衡处理；
- 概率阈值；
- Balanced 作为重要选择指标。

### 5.3 March 与 August 显示 Raw 不能脱离基线看

March 的 all-negative baseline 已达到约 51.48%，模型 Raw 也约 51.61%。

这意味着：

> 单看 Raw 几乎无法证明模型真正学到双边方向规律。

必须同时看 Balanced 和 recalls。

## 7. 为什么 current standalone 与历史 Cycle88 不完全相同

本包是独立重构，差异可能来自：

- 模型参数略有不同；
- 数据冻结方式不同；
- feature cube 组织不同；
- 缺失值处理实现差异；
- 原 Cycle88 内部 helper / temporary artifact 没有复制；
- seed / library version / LightGBM 实现细节。

因此合理的表述是：

> “复现了 Cycle88 segmented LightGBM 的核心思路和严格时间合同。”

而不是：

> “精确复现 Cycle88 历史数字。”

## 8. 当前实验的主要失败模式

综合历史 Cycle88、Cycle89 和 standalone 结果，目前最稳定的失败特征是：

```text
1. 跨月 Raw 长期约55%-60%
2. Positive / Negative recall 经常严重不平衡
3. Balanced 多数时间仅50%-55%
4. 小开发窗口可能出现65%+，完整月份后回落
5. 单纯增加模型复杂度未带来稳定提升
6. MAE较好时方向仍可能一般
```

因此下一阶段不能继续只问：

```text
“再换哪个回归模型？”
```

而应该分别回答：

```text
方向 objective 是否错配？
类别不平衡是否是主要原因？
概率排序能力到底有没有？
阈值是否不合理？
哪个 backbone 在完全相同协议下更强？
哪些市场状态最容易失败？
```

## 9. 后续任何结果建议使用统一表格

至少：

| Scope | Model | Raw | +Recall | -Recall | Balanced | AUC | Brier | MAE | Leakage |
|---|---|---:|---:|---:|---:|---:|---:|---:|---|

并分别报告：

```text
overall
by month
by period (1-8 / 9-16 / 17-24)
```

分类模型另外报告：

```text
predicted positive rate
true positive rate
probability calibration
threshold
```

这样才能判断“分高”究竟是模型能力、类别偏置，还是阈值造成。

---

## 10. 晋级标准

建议后续模型只有在以下条件同时满足时才称为有效提升：

```text
STRICT/PASS
多数月份方向不低于父基线
总体 Raw 实质提升
Balanced 同步改善
少数类 Recall 不collapse
不是靠单一月份
不是靠测试集调 threshold
确认集仍成立
```

老师要求的 70% 应当作为跨月最终目标，而不是通过选择最好月份或最好阈值事后拼出来的数字。
