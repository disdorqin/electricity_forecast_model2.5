# 06 历史实验与版本选择

## 1. 为什么必须保留历史路线

24 点价差项目已经经历多轮实验。很多路线曾在短窗口出现漂亮数字，但后续因为：

- 信息泄漏；
- 符号口径变化；
- 跨月失效；
- 少数类 collapse；
- 复杂模型在完整月份回落；

被降级或作废。

因此本项目不能只保存“当前最好数字”，而要保存：

> 为什么当时这么做、结果是什么、为什么继续/停止。

这也是本审查包选择 Cycle88 透明 LightGBM 而不是直接展示某次局部最高分的原因。

---

## 2. 第一阶段：传统 24 点 direct-spread 路线

早期主要围绕：

```text
历史价差
基本面 forecast
LightGBM / CatBoost
Similar-Day / P6
特征工程
```

进行实验。

这一阶段得到的重要认识不是某个模型名字，而是：

1. 方向任务长期比数值回归更难；
2. 正/负类经常不平衡；
3. 单月可以做到 60%+，但跨月很难稳定；
4. `9-16` 时段通常更难；
5. 模型对 forecast fundamental 有利用，但仍不能稳定解释 RT 的未来冲击。

---

## 3. 泄漏事故：为什么后来把标准改得非常严格

### 3.1 P6 + Similar-Day 约 69.44% 作废

某轮实验曾得到接近老师目标的结果，后审计发现：

```text
预测 D
却把 D-1 完整24点标签放进训练
```

由于 forecast origin 是 D-1 14:00，D-1 h15-h24 尚未发生，因此这属于未来标签泄漏。

结果全部作废。

### 3.2 96→24 约 73%-78% 作废

96 点上游一度得到非常高的方向结果，并通过 aggregator 聚合到 24 点；后来发现上游预测时使用了正式业务时点不可获得的信息。

虽然最终评价的 24 点真值没有问题，但：

```text
leaky upstream prediction -> clean downstream label
```

整条链路仍然无效。

这两次事故最终形成今天的固定规则：

```text
D-1 14:00 origin
D-2 complete-label cutoff
D-1 only h1-h14 context
all secondary learning also causal
final holdout protected
```

---

## 4. Cycle87：冻结旧路线参考

Cycle87 被保留为一个 locked reference，主要作用是：

- 保存此前 strict route 的完整证据；
- 给后续 Cycle88 提供可回滚基线；
- 防止新实验不断覆盖旧“当前最好”。

但 Cycle87 的历史符号合同仍属于 legacy `RT-DA` 路线。因此与当前 `DA-RT` 的正/负方向指标比较时必须先做语义对齐。

---

## 5. Cycle88：正式切换到数值 DA-RT

Cycle88 明确建立：

```text
Spread = DA - RT
Forecast origin = D-1 14:00
Training labels <= D-2
Target-day actual forbidden
Target-day DA feature forbidden（当前strict合同）
```

目标是建立一条更容易解释、可跨月审计的 numeric spread 主线。

### 5.1 初始 numeric_v2

2026-06 + 2026-07 quick screen 中：

```text
Raw ≈ 58.74%
Balanced ≈ 53.41%
MAE ≈ 87.85
```

但完整 Jan-Aug14 跨月后回落到：

```text
Raw ≈ 54.91%
+Recall ≈ 67.09%
-Recall ≈ 36.44%
Balanced ≈ 51.76%
MAE ≈ 83.82
```

这说明两个月 quick screen 的结果不能代表稳定泛化。

---

## 6. Cycle88 优化第一轮：分段 LightGBM

在不改变 DA-RT 目标、不引入未来信息的前提下，测试：

```text
训练样本正负平衡
1-8 / 9-16 / 17-24 分段
二者组合
```

最终暂时选择：

```text
numeric_v2 / full F0-F9 + lgbm_segmented
```

严格跨月历史结果：

```text
Raw                ≈ 56.35%
+Recall            ≈ 68.00%
-Recall            ≈ 38.67%
Balanced           ≈ 53.34%
MAE                ≈ 84.09
RMSE               ≈ 132.73
```

相对前一全局模型，大约提升：

```text
Raw      +1.44 pp
Balanced +1.57 pp
-Recall  +2.23 pp
```

这是有价值但有限的改进：

> segmentation 有帮助，但距离 70% 很远。

因此不能继续靠“小调几棵树”期待解决根本问题。

---

## 7. 特征筛选与加树实验：为什么没有继续堆传统优化

Cycle88 后续做过：

- gain / PFI / consensus feature ranking；
- feature ladder；
- confirmation；
- 去 early stopping / 增加树数量等。

整体发现：

> 特征筛选大约只带来 1 个百分点量级的改善；单纯加树、延长训练并没有产生结构性突破。

因此研究重点从“再调一点 LightGBM”转向：

- 任务 formulation；
- direction objective；
- 深度时序模型；
- 概率决策层。

---

## 8. Cycle89：N-BEATSx 深度路线

Cycle89 是一次更系统的深度模型尝试。

它不是简单把 LightGBM 换成神经网络，而是实现了：

```text
NBEATSx
D-1 14:00 strict origin
D-2 training cutoff
H34 direct horizon
CORE5 forecast covariates
36个月历史
chronological validation
```

并进一步实验：

- long-history；
- compact features；
- DIRECT_H34；
- gap-direct；
- bridge teacher forcing；
- DIRMO；
- loss/objective。

### 8.1 为什么曾经看起来很有希望

在 DEV14 小型开发面板上，部分 N-BEATSx 结果一度达到约 65%-68% 的方向水平，因此值得继续扩展。

### 8.2 为什么最终没有替代 Cycle88

完整 FULLDEV5（Jan/Feb/Apr/Jun/Jul，150日）后：

| 模型/策略 | Raw | +Recall | -Recall | Balanced | MAE |
|---|---:|---:|---:|---:|---:|
| NBEATSx DIRECT_H34 | 52.53% | 55.49% | 47.84% | 51.66% | 99.18 |
| NBEATSx DIRMO | 52.75% | 57.62% | 45.04% | 51.33% | 103.29 |
| Cycle88 strict LGBM comparator | 56.12% | 70.44% | 33.38% | 51.91% | 87.24 |

关键教训是：

> 小型 DEV 面板上的 65%+ 并没有转化成完整跨月稳定能力。

N-BEATSx 减少了部分 majority-collapse，但没有稳定提高最终 Raw / Balanced，且训练成本显著更高。

因此 Cycle89 没有取代 Cycle88 作为当前可审查基线。

---

## 9. 为什么师兄审查包最终选择 Cycle88 segmented LightGBM

不是因为它历史 Raw 最高，而是它在以下几项之间最均衡：

```text
当前 DA-RT 正确口径
严格 D-1 14:00 / D-2 边界
有完整跨月证据
模型透明
训练快速
F0-F9 可解释
易于独立复现
容易继续加方向分类器
```

这比拿一个局部 65% 或已经作废的 73%-78% 高分给师兄更有审查价值。

## 10. Direction-Magnitude：老师当前建议已经开始验证

老师最新建议的核心是：

```text
不要只让回归器间接决定方向
直接训练 P(Spread > 0)
回归器只负责 magnitude
```

Cycle88 已做第一阶段干净对照：

### 10.1 默认 Direction-Magnitude

selection（2026-03 + 2026-05）中：

```text
Signed-regression C0:
Raw      ≈ 56.85%
Balanced ≈ 56.10%
MAE      ≈ 82.66

Direction-Magnitude C1:
Raw      ≈ 56.12%
Balanced ≈ 54.31%
MAE      ≈ 99.32
```

单纯拆成分类方向 + abs(spread) 幅值，并没有直接优于 signed regression；尤其 negative recall 和数值误差恶化。

这说明：

> “拆 target”这个方向值得研究，但不是简单换一个 classifier 就会自动提升。

### 10.2 `is_unbalance=True`

在同一 C1 结构上加入 LightGBM 类别不平衡处理后：

```text
Raw      56.12% -> 56.45%   (+0.34pp)
Balanced 54.31% -> 54.87%   (+0.56pp)
-Recall  43.11% -> 45.03%   (+1.92pp)
```

但：

- +Recall 略降；
- AUC / logloss 没改善；
- 月份间不完全一致；
- 改善远不足以达到目标。

因此当前结论应是：

```text
weak signal, not promotion
```

而不是“is_unbalance 已解决问题”。

## 11. 当前真正需要回答的三条路线

结合全部历史证据，现在最有价值的并行问题是：

### A. 目标函数 / 分类方向

回答：

> 方向性能差，是不是因为 regression objective 与业务 sign 目标错配？

测试 default binary、unbalance、class weight、magnitude head 等。

### B. Backbone

回答：

> 在相同严格信息和特征下，LightGBM 是否已经接近当前特征的能力上限？

建议优先比较：

```text
LightGBM
CatBoost
TabPFN v2
TabM
```

TimeMixer 已经有历史实验，不必为了“模型多”机械重复。

### C. Decision / Calibration / Validation

回答：

> 模型是否其实学到了部分概率排序能力，只是 0.5/0 阈值和评价方式不合理？

需要做：

- OOS probability ledger；
- walk-forward；
- Platt / isotonic；
- threshold search；
- global vs period threshold；
- threshold stability；
- calibration diagnostics；
- month/period/error-state 分析；
- 最终 frozen replay。

这三条路线互相独立，又能在最后汇合。

---

## 12. 版本选择原则

后续任何新路线只有同时满足下面条件，才有资格替换当前基线：

```text
STRICT/PASS
跨月份
Raw有实质提升
Balanced不下降，最好同步提升
正负Recall不出现新collapse
不是靠类别比例取巧
确认集也成立
测试集没有参与阈值/特征/模型选择
复杂度增加有对应收益
```

模型名字更新、网络更深、论文更新，都不是晋级理由。
