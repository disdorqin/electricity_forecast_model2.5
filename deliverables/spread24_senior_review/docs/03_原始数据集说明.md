# 03 原始数据集说明

## 1. 数据包定位

本审查包不是把整个原项目的数据仓库完整复制过来，而是提供一份用于独立审查与固定复现的冻结数据。

默认运行入口读取：

```text
data/frozen_repro/slot_table.parquet
```

同时配套：

```text
feature_groups.json
feature_registry.json
manifest.json
```

`raw_reference` 若存在，仅用于追溯和人工审查，不是默认运行时重新构造全部特征的入口。`python run.py --rebuild-from-raw` 目前也不会真正覆盖 frozen reproduction 数据。

因此要区分两个概念：

- **原项目 canonical 数据**：用于完整研究、重新构造 feature cube；
- **本审查包 frozen_repro**：用于让师兄在不依赖原项目脚本/绝对路径的情况下复核同一套输入结构和训练逻辑。

---

## 2. 原始业务字段类型

24 点 canonical 数据主要可以分成四类。

### 2.1 Price / Label 类

核心价格字段：

```text
DA 日前电价
RT 实时电价
Spread = DA - RT
```

其中目标日 `D` 的 DA / RT / Spread 在本 strict direct-spread 合同中都不作为 target-day 输入，Spread 是监督标签。

### 2.2 Forecast fundamental 类

主要包括：

- 地方电厂总加；
- 联络线受电负荷；
- 风电总加；
- 光伏总加；
- 核电总加；
- 自备机组总加；
- 试验机组总加；
- 直调负荷；
- 竞价空间；
- 新能源总加。

如果这些 forecast 在 `D-1 14:00` 已经对目标日 D 发布，则可以进入 target-day 特征。

### 2.3 Actual fundamental 类

与上述运行量对应的 actual 值，只能：

- 用于 D-2 及更早的历史统计；
- 用于历史 forecast error；
- 用于标签/数据质量审计。

**目标日 D 的 actual 不得进入特征。**

### 2.4 Calendar / Audit 类

例如：

- 日期；
- 小时；
- day of week；
- 业务日索引；
- source timestamp / available timestamp；
- 数据来源与角色标签。

日历变量属于预测时已知信息。

## 3. 当前 frozen slot table 的基本合同

测试 `tests/test_data_contract.py` 目前检查：

```text
总行数 = 40670
period ∈ {1_8, 9_16, 17_24}
target_direction 与 target_spread 的符号一致
```

冻结表中的每一行对应一个目标日、一个小时、一个 period，以及该时点的目标和特征。

实际可用于某个目标日训练的行，不由“表里有没有”决定，而由训练时的日期边界过滤决定：

```text
training_last_day = D-2
```

因此 frozen table 可以同时包含未来评估期标签，但训练代码必须按目标日严格切片。

## 4. 竞价空间与“直调负荷-新能源”必须区分

历史实验中一个重要业务语义问题是：

> 老师/师兄口头所说的“竞价空间≈直调负荷-新能源”，与原始系统中存储的“官方竞价空间”字段不一定是同一物理定义。

Cycle88 的处理原则是：

- 不覆盖原始 `fcast_竞价空间`；
- 另行构造清晰命名的 derived quantity，例如：
  - `renewable_adjusted_direct_load`
  - `residual_load_renew`
  - `bidding_space_ratio`
  - `space_definition_gap`
- 让模型自行比较这些定义是否提供额外信息。

禁止为了符合口头解释，直接把官方字段重命名或覆盖成另一个公式。

## 5. 数据真实性与 24/96 口径必须隔离

项目曾经出现 96 点 `actual_*` 与 `fcast_*` 大面积重复的数据污染事故，因此：

> 96 点数据的真实性结论不能直接迁移到 24 点，也不能因为 96 点表字段名叫 `actual` 就默认可信。

本 24 点审查包只服务于 24 点 strict spread 路线。若未来接入 96 点或 96→24：

1. 必须先审计 96 点 forecast / actual 来源；
2. 必须单独检查上游 forecast origin；
3. 不得把被污染的历史 96 点特征重新作为生产/正式研究输入；
4. 只有上下游都通过因果审计，最终 24 点结果才有效。

## 6. 数据质量检查重点

重新构造或扩展目标日期时，至少检查：

```text
每个业务日是否24点完整
DA / RT / Spread 是否 finite
forecast fundamental 是否存在异常数量级
新能源与风+光的关系是否合理
actual/fcast 是否异常完全一致
目标日 actual 是否意外混入特征
D-1 context 是否超过14点
```

Cycle88 历史审计曾记录 `2026-08-15 15:00`、`16:00` 附近新能源/光伏 actual 出现百万量级异常值，因此向后扩展实验时不能机械认为 canonical 所有行天然干净。

---

## 7. 缺失值原则

本独立包当前在每个 rolling train slice 内：

```text
train missing -> train median -> 仍缺失则0
test missing  -> 对应 train median -> 仍缺失则0
```

关键原则不是“必须用 median”，而是：

> 任何填充值都只能由当时可用的训练数据计算，不能用包含未来测试期的全表统计量。

因此禁止：

```text
先对整张2022-2026表算全局median
再切train/test
```

这会让未来分布信息回流到过去。

---

## 8. frozen_repro 与原始 Cycle88 的关系

本包是从 Cycle88 思路独立重构出来的审查版本，不是把 Cycle88 feature cube 和 runner 原样复制。

因此：

- frozen_repro 主要用于可审查性、便携性；
- 原 Cycle88 正式科研证据仍以原实验目录 manifest / run 产物为准；
- 本包运行结果和 Cycle88 历史指标存在小幅差异是允许的；
- 任何“精确复现 Cycle88”的说法都不准确。

如果需要重新进行正式科研结论，应回到项目 canonical + strict experiment runner，而不是只依赖这个便携审查包。
