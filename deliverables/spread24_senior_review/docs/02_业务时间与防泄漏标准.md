# 02 业务时间与防泄漏标准

## 1. 这份文档是整个 24 点价差实验的最高优先级约束

在本项目里，**防泄漏优先级高于模型精度**。任何结果如果事后发现使用了预测时刻不可获得的信息，无论 Raw、Balanced 或 MAE 多漂亮，都必须立即作废，并标记为 `INVALID-LEAKAGE`。

本任务的关键不是“日期上是不是过去”，而是：

> 在 `D-1 14:00` 这个真实预测时点，这个信息到底已经完整发生并可以被业务系统拿到没有？

历史上项目曾出现过两类非常典型的伪高分：

1. 96→24 路线曾得到约 73%-78% 的方向结果，但后审计发现上游 96 点预测使用了正式预测时点拿不到的信息；最终 24 点真值本身虽然干净，但整条链路仍然无效。
2. P6 + Similar-Day 路线曾出现约 69.44% 的漂亮验证结果，后查出训练集把 `D-1` 完整 24 点标签当成历史监督标签使用；在 `D-1 14:00` 时，15-24 点尚未发生，因此该结果作废。

这两次事故形成当前严格协议。

---

## 2. Forecast origin 固定

预测目标日记为 `D`。

本任务固定：

```text
Forecast origin = D-1 14:00
```

也就是说，在 `D-1 14:00` 做出对 `D` 日 24 个小时的一次性预测。

这个时点一旦固定，所有数据都必须按“当时是否可见”划分，而不能只按日期字段大小判断。

---

## 3. 允许与禁止的信息

### 3.1 允许使用

#### A. D-2 及更早的完整历史

包括：

- 历史 DA；
- 历史 RT；
- 历史 Spread；
- 历史实际负荷/风电/光伏/新能源等；
- 历史 forecast 与 actual 的误差；
- 历史统计量、regime、uncertainty；
- 历史模型 OOS 预测结果，只要这些预测在当时也是严格因果生成的。

因为这些日子的 24 小时信息在 `D-1 14:00` 已经完整落地。

#### B. D-1 当天 14:00 以前已经发生的信息

只允许：

```text
D-1 h1 ... h14
```

例如：

- 已发生的 D-1 spread h1-h14；
- 已发生的 D-1 RT h1-h14；
- 由这些可见点计算出的 mean/std/median/slope/positive rate；
- 1-14 点原始轨迹。

这些信息可以作为 **context feature**，但不能因此把 D-1 整天当作完整训练样本。

#### C. 目标日 D 的提前发布 forecast-type 信息

如果业务上确认在 `D-1 14:00` 已经发布，则可使用：

- forecast 直调负荷；
- forecast 风电；
- forecast 光伏；
- forecast 新能源；
- forecast 竞价空间；
- forecast 联络线；
- forecast 地方电厂/核电/自备/试验机组；
- 日历、小时等确定性未来信息。

当前 Cycle88 strict direct-spread 合同默认 **target-day DA 不作为输入特征**，避免不同业务解释下的可得性争议。本审查包也沿用这一保守口径。

---

### 3.2 明确禁止使用

预测 D 时，以下信息不得进入任何一级或二级学习：

```text
D-1 h15-h24 realized RT / spread / actual fundamentals
D 日 RT
D 日 spread
D 日 actual fundamentals
D 日任何事后修正后的实际量
D-1 完整24点 spread 标签
```

并且不只是“不得进模型特征”。它们同样不能进入：

- threshold 调整；
- Platt / isotonic calibration；
- stacking；
- ensemble weight；
- gating / router；
- feature selection；
- similar-day label pool；
- regime prior；
- early stopping；
- 超参数选择；
- model selection；
- checkpoint selection。

**二级学习同样受 forecast origin 约束。**

---

## 4. 为什么训练标签必须截止 D-2

预测 D 的时点是 `D-1 14:00`。

此时：

```text
D-1 h1-h14 已发生
D-1 h15-h24 尚未发生
```

因此 D-1 不是一个完整监督训练日。

完整监督训练标签必须满足：

```text
training_last_day <= D-2
```

例如预测 `2026-07-10`：

```text
Forecast origin       = 2026-07-09 14:00
Last complete label   = 2026-07-08
```

不能因为 `2026-07-09 < 2026-07-10` 就把 7 月 9 日整天标签放进训练。

这也是为什么下面这类写法非常危险：

```python
train = df[df.day < target_day]
```

日期条件成立不等于业务可见性成立。

---

## 5. 当前滚动训练方式

本审查包当前使用：

```text
rolling training window = 180 complete days
training_last_day = D-2
training_first_day = training_last_day - 179 days
```

每预测一个新的目标日，都重新向前滚动。

示意：

```text
预测 D1： [过去180个完整日] -> D1
预测 D2：   [过去180个完整日] -> D2
预测 D3：     [过去180个完整日] -> D3
```

这与随机 train/test split 完全不同。

本包 `src/leakage.py::training_last_day()` 显式实现 D-2 截止；`src/pipeline.py` 每个目标日重新计算训练窗。

需要注意：本审查包的 leakage audit 是为了独立审查而做的轻量实现；项目正式研究链路还会要求更完整的 feature-source audit、counterfactual audit、holdout audit 等。不能因为本包 CSV 写了 PASS 就认为任意新实验天然安全。

## 6. Walk-forward / Prequential 是什么

Walk-forward 的核心只有一句话：

> 永远用过去生成预测，再把时间向前推进；任何选择都只能利用当时已经发生的 OOS 历史结果。

例如要为 7 月确定分类阈值：

```text
更早历史 -> 预测4月
更新可用历史 -> 预测5月
更新可用历史 -> 预测6月
```

得到 4-6 月一串真实的、当时可生成的 out-of-sample 概率：

```text
prob_positive, y_true
```

只允许在这些历史 OOS 结果上：

- 拟合 Platt calibration；
- 搜索 decision threshold；
- 选择模型；
- 选择权重。

然后把所有规则冻结，再评价 7 月。

禁止：

```text
看7月真值 -> 找7月最佳threshold -> 再汇报7月
```

那等价于拿测试集调参。

## 7. Selection / Validation / Confirmation / Final Holdout

严格实验必须区分不同数据角色。

### 7.1 Development / Selection

用于：

- 初步筛选 idea；
- 判断某个单变量改动有没有信号；
- 诊断失败原因。

一旦反复使用，这些月份就已经成为开发证据，不能再宣称它们是“全新测试”。

### 7.2 Confirmation

在方案结构、主要超参数、阈值策略已经冻结后，使用此前未参与选择的时间块确认跨月泛化。

### 7.3 Final Holdout / Lockbox

必须在以下内容全部冻结后才打开：

```text
feature set
model family
loss
training protocol
calibration
threshold
router / ensemble rules
```

最终留出集一旦打开并用于继续迭代，就不再是 final，需要寻找新的未来时间块作为 lockbox。

Cycle88 / Cycle89 历史实验曾专门保留 final holdout / September lockbox，就是为了避免长时间研究中“测试集逐渐变训练集”。

## 8. 概率校准和阈值也必须防泄漏

后续方向分类器会输出：

```text
p = P(Spread > 0)
```

默认规则是：

```text
p >= 0.5 -> positive
```

但如果需要优化阈值 `tau`：

```text
p >= tau -> positive
p < tau  -> negative
```

则 `tau` 只能由 **过去的 walk-forward OOS 预测**确定。

Platt calibration 也是一样。不能在目标测试月上 fit calibration，再把校准后的结果当成测试成绩。

对每个目标日/目标月都要保证：

```text
calibration_data_date < target evaluation block
threshold_selection_data < target evaluation block
```

更严格地说，还要满足这些 OOS 概率本身当时的模型训练标签截止规则。

---

## 9. Similar-Day / KNN / Analog 的特殊规则

如果后续恢复类似日路线：

```text
latest_candidate_day <= D-2
```

距离计算只能使用预测时点已知 descriptor。

候选日的历史 spread label 可以用，因为它已经完整发生；目标日、D-1 未完成部分不能用。

每个目标日最好记录：

```text
latest_candidate_day
candidate_count
feature_cutoff
```

并做硬断言。

---

## 10. 96→24 路线的额外规则

下游 24 点真值干净，不代表整条链路没有泄漏。

如果使用 96 点模型或 96→24 aggregator：

1. 先审计 96 点数据源；
2. 先审计 96 点模型的 forecast origin；
3. 上游任何 target-day actual / post-cutoff realized 使用都会使下游结果失效；
4. aggregator 的训练、阈值和 selection 同样必须因果；
5. 只有整条上游+下游都 STRICT/PASS，24 点最终成绩才可进入正式比较。

历史 96→24 高分被撤回，正是因为忽视了“上游信息边界”。

## 11. 每次新实验必须记录的最小 manifest

至少包含：

```json
{
  "target": "DA-RT",
  "forecast_origin": "D-1 14:00",
  "training_last_day_rule": "D-2 or earlier",
  "d1_post14_realized_as_feature": false,
  "target_day_actual_as_feature": false,
  "target_day_DA_as_feature": false,
  "selection_period": "...",
  "confirmation_period": "...",
  "final_holdout": "...",
  "final_holdout_touched": false,
  "leakage_status": "STRICT/PASS"
}
```

如果缺少关键信息边界，只能标记：

```text
LEGACY-UNVERIFIED
```

不得与严格正式结果并列。

---

## 12. 推荐的 leakage status

统一使用：

```text
STRICT/PASS        完整按业务时点审计通过
ORACLE/PRIVILEGED  明确使用未来/特权信息，仅用于上限诊断
INVALID-LEAKAGE    已确认泄漏，成绩作废
LEGACY-UNVERIFIED  历史产物，信息边界无法完整证明
```

不要只写 `PASS`，必须说明是哪一种合同下的 PASS。

## 13. 新实验开跑前 checklist

任何组员开跑前都应该逐项回答：

```text
[ ] Spread 符号是否固定 DA-RT？
[ ] Forecast origin 是否明确为 D-1 14:00？
[ ] 完整训练标签最后一天是否 <= D-2？
[ ] D-1 只使用 h1-h14 已发生 context？
[ ] 是否使用任何 D-1 h15-h24 realized？若是，立即停止。
[ ] 是否使用 target-day actual？若是，立即停止。
[ ] Target-day forecast 特征是否确实在 origin 前发布？
[ ] Feature selection 是否只使用开发期？
[ ] Early stopping 是否读取未来块？
[ ] Threshold/calibration 是否来自历史 OOS walk-forward 结果？
[ ] Confirmation/final holdout 是否未参与调参？
[ ] 是否同时报告 Raw、+Recall、-Recall、Balanced 和类别 baseline？
[ ] 是否按月报告，而不是只报 pooled overall？
```

只要其中任何一项无法回答清楚，就先审计，不要训练。
