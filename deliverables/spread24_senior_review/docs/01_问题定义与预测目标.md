# 01 问题定义与预测目标

## 1. 任务一句话定义

本审查包对应山东电力市场 **24 点（小时级）日前-实时价差预测**任务：

> 在目标日 `D` 的前一日 `D-1 14:00`，一次性预测 `D` 日 24 个小时的价差，其中本包统一采用
>
> `Spread(D,h) = DA(D,h) - RT(D,h)`。

模型既需要输出连续价差数值，也需要给出价差方向。对任意小时 `h`：

```text
Spread > 0  -> 正方向（DA > RT）
Spread <= 0 -> 负方向（DA <= RT）
```

本包当前主模型仍是连续值回归模型，因此方向由预测价差的符号派生：

```text
pred_direction = 1(predicted_spread > 0)
```

需要特别说明：项目历史较早路线曾使用过 `RT - DA` 作为符号约定。Cycle88 数值价差路线以及本审查包已经切换并冻结为 **DA - RT**。跨版本比较时必须先核对符号合同，不能只看“正/负召回”字样直接横向比较。

---

## 2. 为什么这是一个比普通价格预测更难的问题

我们的最终业务要求并不只是“价格数值误差尽量小”。老师当前硬要求是 **方向准确率跨月份稳定达到至少 70%**。这使任务同时具有两个目标：

1. **连续值目标**：尽可能准确地估计 `DA - RT` 的幅值；
2. **方向目标**：正确判断 `DA - RT` 的正负。

这两个目标并不完全一致。例如真实价差为 `+1`，预测为 `-1`，数值误差只有 2，但方向完全错误；真实价差为 `+100`，预测为 `+40`，数值误差很大，但方向正确。因此：

> `MAE` 很好并不自动意味着方向很好，反之亦然。

这也是后续老师提出“方向分类器 + 幅值回归器”拆分方案的根本原因。

## 3. 当前正式评价指标

所有实验至少同时报告以下指标，禁止只报一个最好看的数字。

### 3.1 Raw Direction Accuracy

```text
Raw = 正确方向点数 / 全部点数
```

它直观、业务上重要，但受类别比例影响。若某个月正类占比很高，模型一直预测正也可能得到较高 Raw，因此 Raw 不能单独作为模型选择标准。

### 3.2 Positive Recall

```text
+Recall = TP / (TP + FN)
```

表示真实为正价差的时点中，有多少被正确识别。

### 3.3 Negative Recall

```text
-Recall = TN / (TN + FP)
```

表示真实为负价差的时点中，有多少被正确识别。

### 3.4 Balanced Accuracy

```text
Balanced = (+Recall + -Recall) / 2
```

这是方向模型是否真正具备双边判别能力的重要指标。当前项目很多历史模型存在“Raw 看起来尚可，但少数类召回塌缩”的问题，因此 Balanced 必须与 Raw 同时报告。

### 3.5 数值指标

至少报告：

```text
MAE
RMSE
```

需要数值价差时，可以继续观察 rMAE / tail MAE / sMAPE 等诊断指标，但方向任务的主要晋级标准不应被纯数值误差取代。

### 3.6 类别基线

每个月至少同时计算：

```text
all-positive baseline
all-negative baseline
```

如果一个模型的高 Raw 主要来自类别比例，而 Balanced 或少数类 Recall 接近随机/塌缩，则不能宣称“方向能力突破”。

## 4. 时间粒度与时段划分

目标日包含 24 个小时：

```text
h1 ... h24
```

Cycle88 以及本审查包当前采用三个时段分别建模：

```text
1_8   : h1  - h8
9_16  : h9  - h16
17_24 : h17 - h24
```

采用分段模型不是业务必须，而是 Cycle88 的受控实验结论：不同日内时段的价格/新能源/负荷机制差异明显，全局单一 LightGBM 在方向偏置和误差结构上表现不稳定；三段独立模型在严格跨月实验中带来了约 1 个百分点量级的方向与 Balanced 改善，因此被保留为透明、可审查的当前基线。

历史分析中 `9-16`（光伏影响显著的时段）长期是更困难的部分，应单独观察，但不允许只挑最好时段汇报。

## 5. 当前研究问题不是“换一个模型就结束”

整个 24 点价差路线目前要区分三个不同问题：

### Q1：特征是否包含足够的可预测信息？

现有 F0-F9 已包括：

- 历史价差；
- D-1 14:00 前已发生上下文；
- D 日提前发布的 forecast fundamentals；
- 负荷/新能源/竞价空间及其组合；
- ramp / profile；
- 历史 forecast error；
- uncertainty / regime。

如果多种模型都长期停在 50%-60%，可能意味着当前可用信息本身对未来 RT 冲击解释力有限。

### Q2：学习目标是否与业务目标错配？

当前回归器优化的是：

```text
L1(target_spread, predicted_spread)
```

而老师真正关心的是：

```text
sign(predicted_spread) == sign(target_spread)
```

因此后续需要直接训练 `P(Spread > 0)` 的二分类器，并与 signed regression 做公平对照。

### Q3：决策规则是否合理？

即使分类器能够输出概率，默认 `0.5` 阈值也未必是跨月 Balanced 最优。因此阈值选择、概率校准和 walk-forward 决策层需要独立实验，同时严格遵守时间边界。

## 6. 当前目标与“70%”的正确解释

项目目标是：

> 在严格 D-1 14:00 信息条件下，跨月份稳定提升 24 点价差方向能力，并最终争取 Raw / Balanced 均接近或达到老师要求的 70% 水平。

以下情况不能视为达到目标：

- 单日或少数日期 >70%；
- 单个月份 >70%，其他月份明显崩溃；
- 全正/全负类别占比导致 Raw >70%；
- 使用目标日 actual、D-1 14:00 后 realized 信息、D-1 完整标签等未来信息得到 >70%；
- 用测试月本身调阈值、调权重、做特征筛选后再汇报该月；
- 96→24 上游曾使用预测时不可得信息，但最终 24 点标签本身是干净的。

因此项目的核心不是“跑出一次 70%”，而是：

```text
STRICT/PASS 信息边界
+ 跨月
+ 可复现
+ 正负类都有效
+ 测试集未用于选择
```

## 7. 本审查包的定位

`spread24_senior_review` 是为了让师兄/老师快速审查当前思路而制作的 **独立、轻量、可运行重构包**。

它的作用是：

- 清楚展示业务合同；
- 展示一条严格 D-2 标签截止的 24 点滚动训练链路；
- 展示 F0-F9 特征的基本结构；
- 复现 Cycle88 思路下的透明 LightGBM 基线；
- 作为后续二分类、校准、backbone benchmark 的统一起点。

它 **不是原始 Cycle88 训练器的逐行/逐位复制**，也不是当前全项目全部研究代码的镜像。因此本包结果和 Cycle88 历史正式实验结果必须分开标注，不能混成“完全复现”。
