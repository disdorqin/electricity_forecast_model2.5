# 04 特征说明

## 1. 总体原则

当前审查包按 `feature_groups.json` 组织 F0-F9。核心原则不是“特征越多越好”，而是：

> 每个特征必须同时说明：来源是什么、在 `D-1 14:00` 是否可得、由哪些日期计算、是否可能携带 target-day actual 或未来标签。

特征只有在信息边界合法之后，才有资格讨论重要性和效果。

---

## 2. F0：历史 Spread + 日历基础

主要字段：

```text
spread_lag2d
spread_lag3d
spread_lag7d
spread_same_slot_28d_mean/std/median/positive_rate
hour_sin/hour_cos
dow_sin/dow_cos
```

### 信息边界

完整历史 spread 至少滞后 2 天，因此预测 D 时不会读取 D-1 未完整标签。

### 作用

- 捕捉同小时的历史方向惯性；
- 捕捉周周期；
- 捕捉长期同 slot 的正负比例；
- 为模型提供最基本的“价差状态先验”。

F0 是最容易解释、最稳定的基础组之一。

---

## 3. F1：D-1 1-14 点可见上下文统计

主要字段：

```text
ctx_spread_mean14
ctx_spread_std14
ctx_spread_median14
ctx_spread_last
ctx_spread_mean3
ctx_spread_min14/max14/range14
ctx_spread_absmean14
ctx_spread_positive_rate14
ctx_spread_negative_rate14
ctx_spread_slope14
```

### 信息边界

只能由：

```text
D-1 h1 ... h14
```

计算。

禁止因为这些点可见，就把 D-1 h15-h24 补齐或把 D-1 整天作为训练 label。

### 作用

它试图回答：

> 在做明天 D 的预测时，今天 D-1 到 14:00 为止，当前市场处于什么价差状态？

这是把“最近市场状态”引入 D 日预测的重要渠道。

---

## 4. F2：目标日 Forecast Fundamentals

主要字段：

```text
fcast_地方电厂总加
fcast_联络线受电负荷
fcast_风电总加
fcast_光伏总加
fcast_核电总加
fcast_自备机组总加
fcast_试验机组总加
fcast_直调负荷
fcast_竞价空间
fcast_新能源总加
```

### 信息边界

这些必须是业务上在 forecast origin 之前发布的 forecast 值。

### 作用

这些是决定供需松紧、可再生出力和市场价格结构的直接基本面输入，也是老师最关心的一组变量。

其中重点通常包括：

```text
直调负荷
风电
光伏
新能源
竞价空间
```

但是否“最重要”必须由严格 OOS 实验确认，不能只凭业务直觉下结论。

---

## 5. F3：供需结构与派生量

主要字段包括：

```text
residual_load_ws
residual_load_renew
renewable_share
wind_share
solar_share
bidding_space_ratio
interconnect_share
renewable_minus_space
fcast_renewable_adjusted_direct_load
fcast_space_definition_gap
fcast_renewable_adjusted_direct_ratio
```

### 作用

单个原始 forecast 值往往不够，价格更多由相对供需状态决定。

例如：

```text
新能源占比高不一定意味着同样的价格行为；
关键还取决于负荷、联络线、竞价空间和其他供给共同处于什么水平。
```

因此 F3 主要将绝对量转成结构性比例/差值。

### 注意

“官方竞价空间”和“直调负荷-新能源”不是自动等价的字段，必须保留清晰命名，不能覆盖原字段。

---

## 6. F4：Ramp / 二阶变化

包括：

```text
ramp_load / ramp2_load
ramp_wind / ramp2_wind
ramp_solar / ramp2_solar
ramp_renewable / ramp2_renewable
ramp_bidding_space / ramp2_bidding_space
ramp_residual_load / ramp2_residual_load
```

### 作用

价格不仅与“水平”有关，也与变化速度有关。

例如：

- 光伏快速爬坡/回落；
- 风电快速变化；
- 负荷晚高峰上升；
- 竞价空间突然收紧；

都可能产生与静态值不同的价格响应。

---

## 7. F5：历史 Forecast Error 统计

这一组较大，针对多个基本面分别构造：

```text
7d mean/std
28d mean/std
28d q10/q50/q90
```

并包含：

```text
err_net_load_*
err_renewable_adjusted_direct_*
delta_renewable_adjusted_direct_*
```

### 核心思想

目标日只有 forecast，没有 actual。

但可以利用 D-2 及更早历史回答：

> 最近一段时间，这个 forecast 通常偏高还是偏低？误差波动有多大？

这是一种“预测误差状态”建模。

### 防泄漏要求

误差必须由已完整落地历史计算：

```text
source_day <= D-2
```

禁止使用 D-1 尚未完整的 actual，也禁止用目标日 actual 事后修正 forecast。

---

## 8. F6：Forecast Uncertainty

主要形式：

```text
uncert_<field>_low
uncert_<field>_mid
uncert_<field>_high
uncert_<field>_width
```

覆盖负荷、风、光、新能源、竞价空间等变量。

### 作用

两个小时即使 forecast point estimate 相同，如果历史上该变量的预测误差稳定性完全不同，价格风险可能不同。

因此 uncertainty 主要告诉模型：

> 当前 forecast 值应该被多大程度信任？

它是状态信息，不是 oracle 未来误差。

---

## 9. F7：Regime / 状态偏离

主要字段：

```text
regime_z_fcast_*
regime_z_residual_load_*
regime_z_renewable_share
regime_z_bidding_space_ratio
regime_high_*
regime_low_*
```

### 作用

用于识别：

- 极高/极低负荷；
- 极高/极低新能源；
- 竞价空间异常；
- 与近期历史均值显著偏离的 forecast 状态。

这是对“市场状态非平稳”的显式刻画。

### 防泄漏

任何 z-score 的中心/尺度必须来自过去可用历史，不能对全评估区间统一标准化后再切时间。

---

## 10. F8：D-1 1-14 点原始 Spread 轨迹

```text
ctxraw_spread_p01
...
ctxraw_spread_p14
```

与 F1 不同：

- F1 是 summary statistics；
- F8 保留原始轨迹形状。

目的是让树模型看到：

> 今天到 14 点为止具体怎么走过来的。

禁止添加 p15-p24。

---

## 11. F9：目标日 Forecast Profile 统计

主要针对目标日 forecast trajectory 计算：

```text
mean
std
min
max
```

覆盖：

```text
直调负荷
新能源
风电
光伏
竞价空间
renewable_adjusted_direct_load
space_definition_gap
```

### 作用

同一个小时的价格可能不仅取决于该小时自己的基本面，也取决于全天 profile，例如：

- 当天整体新能源是否异常高；
- 当天负荷峰谷差是否大；
- 当前小时处于整个 profile 的什么位置。

因为使用的是目标日提前发布 forecast profile，所以在业务合同确认可得的情况下是合法未来协变量。

---

## 12. 为什么不是“把 actual 全删掉就天然无泄漏”

泄漏不仅可能来自直接列名 `actual_*`。

还可能来自：

- 用目标日 actual 生成的派生特征；
- 用 D-1 完整 24 点 spread 算的统计量；
- 对全数据做标准化/median；
- 用测试月 label 做 feature selection；
- 用未来 OOS 结果调 threshold；
- Similar-Day 候选池误收 D-1；
- 上游 96 点模型已经看过未来，随后其预测被当作“普通特征”传下来。

因此必须审计 **数据来源与计算时间**，而不是只检查列名。

---

## 13. 特征筛选也必须严格时间化

Cycle88 曾做过 gain、PFI、consensus 等特征筛选。正确原则是：

```text
开发集上选择特征
-> 冻结特征列表
-> 新鲜确认集评价
```

不能：

```text
全 Jan-Aug 真值 -> PFI筛选 -> 再报告 Jan-Aug
```

否则即使单个特征本身合法，选择过程也泄漏了测试标签。

历史特征筛选最终只带来约 1 个百分点量级提升，也说明当前瓶颈并不是“再多删几列”就能解决。

---

## 14. 下一阶段使用这些特征的原则

方向分类、CatBoost、TabPFN、TabM 等新 backbone 第一轮都应该尽量 **复用同一冻结特征输入**。

原因是只有这样才能回答：

> 提升来自模型/目标函数，还是来自特征变化？

第一轮不要同时：

```text
换模型 + 换特征 + 换训练窗 + 换阈值
```

否则无法归因。
