# 文档体系与维护架构

> status: active
> 日期：2026-09-20
> 维护入口：本文件与 `docs/README.md`
> 目标：让人和 AI 都能快速判断“某个问题应该看哪个文档、内容应该写在哪里”。

## 1. 总原则

项目文档采用“少量权威文档 + 领域内持续更新 + 历史材料归档”的结构：

1. 普通改动优先更新已有权威文档，不因为一次修改新建一份报告；
2. 新文档只有在新增长期职责、独立交付对象或独立决策域时才创建；
3. 实验记录、Agent调查、一次性验收和旧方案不属于当前设计，统一归档；
4. 代码、测试和 manifest 是行为事实，文档不能替代验证；文档与代码冲突时，以代码和测试为准，并立即修正文档；
5. 每份 active 文档只能有一个主要职责，不能同时承担架构、运行手册、数据契约和实验记录。

## 3. 代码目录与文档领域的对应关系

| 代码领域 | 主要目录 | 应更新的文档 |
|---|---|---|
| 数据同步、爬虫、数据快照 | `scripts/sync/`、`scripts/crawler/`、`data/` | 数据契约、数据质量、运行手册 |
| 模型适配器、特征、训练 | `runners/`、`TimesFMBackend/`、模型子目录 | 数据契约、防泄漏、工程治理；长期设计另设模型专项 |
| 预测、权重、融合、分类器 | `pipelines/`、`fusion/` | 运行手册、输出契约、项目架构 |
| 回归、审计、验收 | `scripts/tests/` | 运行手册、数据质量、防泄漏 |
| 运行产物、模型权重、日志 | `outputs/`、`dist/` | 输出契约；产物本身不进入 docs |
| 实验、论文、调研 | `scripts/experiments/`、`docs/archive/` | 只有稳定结论进入对应权威文档，其余归档 |
| 长期科研创新候选 | `docs/research_innovation_candidates/` | 已获用户批准、可能长期演化为论文创新点的机制；具体实验仍在 experiments，生产规则仍以权威文档为准 |

## 4. 分支与文档更新边界

使用 `codex/` 前缀的功能分支，并按主要领域命名：

```text
codex/data-*       数据、同步、防泄漏
codex/model-*      模型、特征、权重、融合
codex/pipeline-*   入口、交付、输出、回归
codex/docs-*       文档治理、目录、依赖、归档
codex/experiment-* 仅实验，不改变生产契约
```

一个分支可以跨域，但必须指定一个主领域；提交说明中写明影响的权威文档。实验分支不能直接改变生产模型池、数据契约或正式输出格式，除非同时完成对应回归和文档更新。

## 5. 新增文档判定与审批流程

### 直接更新旧文档

- 只是新增命令、参数、字段、测试结果或一个已有设计的修订；
- 只是补充某个文件夹职责；
- 只是记录一次修复后的结论；
- 只是把旧文档中的过时数字替换为新结果。

### 可以申请新增 active 文档

同时满足以下条件时，智能体才可以提出新增申请：

1. 内容属于一个长期维护的独立领域；
2. 现有权威文档没有合适归属；
3. 文档有明确读者、输入、输出和维护人/维护模块；
4. 申请中写明文档名称、所属领域、不能合并的原因、维护内容和验证方式。

申请必须通过回复发送给用户。**用户明确同意前不得创建文件、目录或占位文档。** 用户同意后，才创建文档，首部标注 `status`、日期、责任领域和验证依据，并登记到 `docs/README.md`。

### 必须归档

- 一次性实验、Agent调研、临时审计、旧验收、过时方案、对话记录；
- 已被新设计取代但仍有追溯价值的内容。

归档时移动文件，不删除内容；生产代码不得依赖归档文档作为唯一行为依据。

## 6. AI 阅读顺序

AI 进入项目后按以下顺序读取：

1. 根目录 `AGENTS.md`：硬约束和禁止事项；
2. `docs/README.md`：当前有效文档索引；
3. 本文：确定问题所属领域和负责文档；
4. 对应领域文档：读取契约、命令和验收标准；服务器部署/历史接续任务先读取 `SERVER_96_STANDARD_SOP.md`，再读取 `SERVER_96_DEPLOYMENT_BACKFILL.md` 补充细节；
5. 代码与测试：核对实际行为；
6. `docs/archive/`：只有在追溯历史决策时读取，不能默认当作现行规则。

AI 新增文档前必须先回答：**为什么不能更新现有负责文档？它属于哪个领域？谁会维护它？如何验证？** 不能回答时，应更新旧文档而不是新建文件；能回答时也必须先请求用户批准。
