## 二、为什么「不能直接移动入口文件」（三维耦合，带代码证据）

`scripts/crawler/collect/crawl_96_local.py:68-90` 存在三重路径耦合：

```python
_FROZEN = getattr(sys, "frozen", False)
if _FROZEN:
    BASE_DIR = Path(sys.executable).parent.resolve()   # ① exe 模式
else:
    BASE_DIR = Path(__file__).resolve().parents[3]     # ② 源码模式：依赖「在 collect/ 下」这一层级

for _p in (str(BASE_DIR), str(BASE_DIR / "scripts" / "crawler")):
    sys.path.insert(0, _p)                             # ③ 注入 scripts/crawler 以支持扁平 import

try:
    from scripts.crawler.collect.crawl import PmosCrawler, ...   # ④ 包路径
    from scripts.crawler.observability import RunReport, ...
except ImportError:
    from crawl import PmosCrawler, ...                            # ⑤ 扁平路径 fallback
    from observability import RunReport, ...
```

**风险点逐条**：

| # | 耦合 | 移动后的后果 |
|---|---|---|
| ② | `parents[3]` = repo root，前提是文件在 `scripts/crawler/collect/` | 移到**同层**（`apps/`）仍 = repo root ✅；移到**更深层**（`apps/96/`）→ `parents[4]` → **路径全错** |
| ③ | `sys.path` 注入 `scripts/crawler` | 层级变了 → 扁平 import 失效 |
| ④⑤ | 双分支 import 兼容「打包 / 源码」两种运行态 | 打包后模块名是扁平的 → 移动会破坏 PyInstaller 静态分析 |
| — | 96 spec `Analysis(['scripts\\crawler\\collect\\crawl_96_local.py'])` | entry 路径须同步改 |
| — | AUX spec `['..\\..\\..\\scripts\\crawler\\collect\\crawl_disclosure_aux.py']` | 同上 |

**结论**：移动入口 = 改 3 处代码耦合 + 2 处 spec + 重新真机验证，**收益低、风险高**。
→ 采用**薄封装（thin wrapper）**替代物理移动：新入口放 `apps/`，逻辑留原地，`__file__` 基准不变。

### 3.1 薄封装示例（零风险的关键）

```python
# scripts/crawler/apps/crawl_96.py
"""96 点爬虫应用入口。

实现仍在 scripts/crawler/collect/crawl_96_local.py，本文件只负责：
  1) 与实现同源地修好 sys.path（apps 与 collect 同层 → parents[3] 一致）；
  2) 转发到实现模块的 main()。
不复制任何业务逻辑，不改变实现模块的 __file__（因此路径/导入逻辑完全不变）。
"""
from __future__ import annotations

import sys
from pathlib import Path

_FROZEN = getattr(sys, "frozen", False)
if _FROZEN:
    _BASE_DIR = Path(sys.executable).parent.resolve()
else:
    _BASE_DIR = Path(__file__).resolve().parents[3]     # 与 collect 入口同一表达式

for _p in (str(_BASE_DIR), str(_BASE_DIR / "scripts" / "crawler")):
    if _p not in sys.path:
        sys.path.insert(0, _p)

from scripts.crawler.collect.crawl_96_local import main   # noqa: E402

if __name__ == "__main__":
    raise SystemExit(main())
```

**为什么零风险**：实现模块的 `__file__` 未变 → `parents[3]`、`sys.path`、双分支 import 全部保持原样。
`apps/` 与 `collect/` 同层，因此薄封装里的 `parents[3]` 也指向 repo root，完全一致。

## 四、风险评估矩阵

| 改动 | 风险 | 依据 / 缓解 |
|---|---|---|
| 新增 `resilience/` | **极低** | 纯新增；96 spec 用 `collect_submodules('scripts.crawler')` 会自动收集；AUX 入口 import 即被收集 |
| 新增 `apps/` + 薄封装 | **极低** | 纯新增；不动 `collect/`；实现模块 `__file__` 不变 |
| 迁移 `platform_review*.py` → `apps/tools/` | **低** | 无 Python import 依赖；仅 `scripts/metrics_24_platform_report.py` 里 1 行字符串提示需同步 |
| 移动 `collect/crawl_*.py` → `apps/` | **高** | 3 处路径耦合 + 2 处 spec 入口，收益低。**不做** |
| 改 `auth/` / `sync_db/` 内部 | **中高** | 共享核心，仅在必需时做，且只做向后兼容加法 |
| 96 接入 resilience（入口接线） | **中** | 只加调用、不改内部；需真机回归 |

## 五、分步实施计划（每步独立可验证，失败可原地回退）

| 步 | 内容 | 风险 | 验证方法 |
|---|---|---|---|
| **S1** | 新建 `resilience/`（9 文件），纯新增 | 极低 | `py_compile` + `python -c "from scripts.crawler.resilience import codes"` |
| **S2** | 新建 `apps/`（薄封装 + README） | 极低 | `python scripts/crawler/apps/crawl_96.py --help` 输出应与原入口**完全一致** |
| **S3** | 迁移 `platform_review*.py` → `apps/tools/` + 改 1 行提示 | 低 | 新路径能跑通导出；`metrics_24_platform_report.py` 提示已更新 |
| **S4** | 96 接入：入口外层包 `guardian.ensure_session` | 中 | 源码模式跑 `--db-check`；真机单日跑通 |
| **S5** | AUX 复用：`_auth` 诊断部分收敛到 `resilience.diagnose` | 中 | 冒烟 + 真机单日 |
| **S6** | 统一编译（96 r6 / AUX r12），真机验证 | 中 | 体积 40~43 MB；报告版本号正确；数据写入正常 |

**总则**：S1/S2/S3 为**纯增量**，与现有 exe 无任何交集，做完即可提交；
S4/S5 才触碰运行逻辑，必须在 S1~S3 全绿后单独进行。
