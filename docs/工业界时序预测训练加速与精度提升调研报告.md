# 工业界电力价格/时序预测：训练加速 + 精度提升调研报告

> 项目背景：山东省电力现货价格预测（24点小时级正式交付 + 96点15分钟级辅助），7 模型（lightgbm / timesfm / timemixer / sgdfnet / rt916，其中 timemixer/sgdfnet/rt916 为 RTX3090 GPU 训练的自研 PyTorch 模型）+ Ledger 自适应融合 + 极端价分类器。
> 痛点：单日训练约 17 分钟，214 天回测需跑约 3 天，训练成本是主要瓶颈。
> 调研日期：2026-08-15。来源见文末「参考资料」。

---

## 0. 调研结论速览（TL;DR）

- **加速最大杠杆不是换硬件，而是「混合精度 + 减少无效 epoch + 特征一次性预计算」三件套**，综合可把 3 天回测压到约 1 天。
- **精度最大杠杆不是换模型，而是「损失函数与评估指标对齐 + 目标变换(asinh) + 多窗口/多seed 集成」**，Lago 2021（本领域最权威综述）实证：**DNN 多 seed 集成显著优于任何单模型**，且短/长双校准窗口平均是统计侧最优实践。
- 电力价格特有的坑：**尖峰/负价（用 asinh 方差稳定变换取代 log，这是 IEEE TPWRS 2018 定下的标准）、节假日、日前负荷/新能源预测是外生变量的最大信息源**。
- 权威来源：Lago et al. 2021 (Applied Energy, arXiv:2008.08004)、Uniejewski et al. 2018 (IEEE TPWRS)、Smith et al. 2018 (ICLR, arXiv:1711.00489)、Loshchilov & Hutter 2017 (ICLR, arXiv:1608.03983)、Leslie Smith 2018 (arXiv:1803.09820)、DeepAR (arXiv:1704.04110)、Chronos (arXiv:2403.07815)、NVIDIA 混合精度官方文档、PyTorch AMP 官方 recipe、Uber 时序不确定性实践 (arXiv:1709.01907)。

## 1. 工业界训练加速 trick（重点，全部可落地）

### 1.1 早停 / 学习率调度：ReduceLROnPlateau vs CosineAnnealing

| 方案 | 原理 | 优点 | 缺点 | 适用 |
|---|---|---|---|---|
| **ReduceLROnPlateau** | 验证损失连续 `patience` 轮不降则 `lr *= factor(0.3~0.8)`，设 `min_lr` | 无需知道总步数；对验证集噪声鲁棒；实现即插即用 | LR 长期偏高会浪费 epoch；对随机初始化敏感；最终常停在浅谷 | 快速 sanity、预算不定、序列短噪音大的场景 |
| **CosineAnnealing**（Loshchilov & Hutter, SGDR 2017）| LR 沿半个余弦周期从峰值衰减到近 0，配合 warm restart 可跳出局部极小 | 确定性、**anytime 性能好**、固定预算下通常收敛到更优极小点 | 需预先定总 epoch/step；`eta_min` 需调 | **滚动日更、每期固定 epoch 预算**的场景（本项目正合适） |
| **1cycle**（Leslie Smith 2018）| 线性 warmup 到峰值 → 余弦退火到近 0，全程 2 段 | **相同精度下 epoch 可减 2~4 倍**；峰值 LR 用 LR Range Test 一次扫出 | 需要先做 LR 扫描；实现比 plateau 复杂 | 训练成本敏感时首选 |

**对本项目的落地建议**：
1. 日更回测是「固定 epoch 预算 + 每天重训」结构 → **主推 `linear warmup (5%~10% steps) + CosineAnnealing`**，并叠加一个「验证集上早停」做安全阀（防止少数天不收敛浪费后段高 LR）。
2. 想再省 2~4 倍 epoch → 对 GPU 模型做一次 **LR Range Test**（1 cycle 里的技巧），直接扫出每模型最优峰值 LR，比网格搜索省一个数量级算力，且 Smith 实证该方案泛化更好。
3. 若只是先验证 pipeline 是否正常，用 ReduceLROnPlateau 当 sanity 即可，不要在生产回测上长期用固定 LR 多跑。

### 1.2 数据加载优化：预读取/缓存/减少 I/O

对时序小数据（214 天 × 每期几百样本），**训练时 DataLoader 的 CPU 开销往往被忽略，但每期重复构建特征矩阵才是隐性大头**。

- **特征矩阵一次性离线预计算（本项目 ROI 最高的加速项之一）**：把 214 天回测需要的全部特征（滞后/滚动统计/日历/外生量）**一次性算好存成 parquet/npy**，回测时每期只按日期切片。不要在 214 次循环里每天重算 rolling/lag/聚合。实测这类重构通常能砍掉每期 30%~70% 的前置耗时。
- **DataLoader 参数**（PyTorch 官方 + 工业实践共识）：
  - `num_workers=2~4`（单 GPU 不必超过 CPU 核数/4），`persistent_workers=True`（避免每 epoch 重建 worker），`prefetch_factor=2~4`，`pin_memory=True`（GPU 拷贝提速）。
  - 数据集若能整体进内存（本规模完全可以），**不要从磁盘按 epoch 重读**。
- **减少 CPU↔GPU 同步**：训练循环里避免每步 `.item()`/打印 CUDA tensor（PyTorch AMP recipe 明确点名）。
- **GPU 侧工程开关**（零成本）：`torch.backends.cudnn.benchmark = True`；`torch.set_float32_matmul_precision('high')`（TF32）；固定输入 tensor 维度避免重分配。

### 1.3 模型层轻量化：减参、蒸馏、量化

- **减参**（对本项目性价比最高）：自研 TimeMixer/SGDFNet/RT916 每日只需拟合「昨日往前 2~4 年」的量级，hidden dim / 层数通常存在 20%~40% 缩水空间而精度不掉（DLinear 在 TSLib 上证明"线性也能打"；TimeMixer 论文也按 look-back 长度分档）。**用参数量 × 每期秒数做一次 scaling 测试**，找精度-成本拐点。每期 GPU 秒数直接决定 3 天回测的墙钟。
- **蒸馏**：从大 teacher 蒸到小 student 对**小模型日更**场景性价比低（teacher 本身就贵），优先级低。
- **量化**：主要省**推理**（每期预测 24/96 点很快），对训练成本无帮助，本任务可忽略。
- **结构级技巧**：patch/下采样（降低序列长度）、共享层、head 用轻量 MLP。TimeMixer 的 multiscale 设计已是这类思路的集大成。

### 1.4 训练策略：warmup、gradient accumulation、batch size

- **Batch size 与收敛速度（Smith et al. ICLR 2018, arXiv:1711.00489）**：实证表明**「增大 batch + 按比例调大 LR」能达到与调 LR 退火完全相同的 train/test 学习曲线，但参数更新次数更少**（ResNet-50 76.1% @ImageNet < 30 分钟）。本项目的 GPU 模型输入是短序列，**batch size 通常可放大 2~4 倍把 GPU 喂饱**，配合 LR 放大（`lr_new = lr_old × sqrt(new_batch/old_batch)` 起步，再上探线性规则），每期步数下降 = 墙钟直接下降。注意在验证集上复验不降精度。
- **Gradient accumulation**：仅当 batch 受显存限制时用（本数据规模基本用不上）；若要用，等价大 batch 同样要配 LR 缩放。
- **Warmup**：Adam + 大 LR 的场景，`linear warmup 5%~10% steps` 可避免前期震荡（与 1.1 的 cosine 配套）。
- **Warm-start / 续训（本回测场景的特有杀器）**：214 天回测是**相邻日高度相关**的任务——**直接加载前一天的模型权重/优化器状态，用少得多的 epoch 续训**（数据只往后移一天）。这是把 3 天回测压到 1.5 天以内最狠的一招，且通常不损精度（平滑适配分布漂移）。注意防泄漏：训练窗口仍只到 target 日前一天，续训只是「初始点 = 前一日权重」。
- **LightGBM 端**（CPU-only，按 skill 勿开 GPU）：`learning_rate` 降到 0.03~0.05 + `n_estimators` 由 early stopping 决定；`feature_fraction`/`subsample`/直方图参数在样本不大时收益小，优先保证早停。

### 1.5 特征工程降低训练成本

- **预计算缓存特征**（同 1.2）：把滞后/滚动统计/日历/外生量全部一次算好；7 个模型**共享同一份 feature store**，避免每模型各自重算。
- **特征选择剪枝**：用 LightGBM 的 `feature_importance` 或与目标的互信息，**剔掉尾部长尾特征**（特征维度降 30% 即可线性省每模型每期时间，且常提泛化）。回归参数丰富模型（LEAR）的经验也证明 LASSO 类隐式选择有效（Lago 2021 §2.1）。
- **避免每期重复做滚动窗口**：rolling mean/std/max 若每天重算 N 天窗口 = O(N) 浪费；离线预计算后每期 O(1) 切片。

## 2. 预测精度提升 trick

### 2.1 时序特征工程最佳实践

- **滞后特征（分口径，勿混）**：本项目 skill 已明确 **24 点用 shift(24)/168，96 点用 shift(96)/672**。在此基础上加**同点不同周滞后**：`shift(7*period)`、`shift(14*period)`，以及**近期一阶/二阶差分**（捕捉最近变化趋势）。
- **滚动统计**：近 3/7/30 天的 rolling mean/std/min/max、近 7 天同时段均值。Lago 综述的 LEAR 即参数丰富 ARX（大量滞后 + 外生），是统计侧精度标杆。
- **日历特征**：小时、星期、月份（one-hot/cyclic sin-cos）、**节假日 flag + 节前/节后 N 天 flag**（电力价格在假期显著不同，Weron 建议测试期至少 1 年就是为了覆盖节假日）。
- **外生变量（日前预测优先）**：日前负荷预测、新能源出力预测、燃料价格（煤/气）、碳价。**Lago 综述的 benchmark 数据集每市场只带两个外生量（负荷+新能源）就能支撑 SOTA**；Shandong 高光伏渗透，正午价格被压低甚至负价，**光伏/风电出力预测的价值尤其大**。
- **多步/多输出结构**：24 点/96 点直接多输出（直接把 24 个目标一次回归）比逐点递归更准更省（DeepAR 的多步输出、TSLib 的 pred_len 一次出）。

### 2.2 损失函数选择（针对电力价格）

| 损失 | 对价格尖峰的行为 | 建议 |
|---|---|---|
| **MSE** | 被尖峰主导，代价是牺牲大多数普通点 | 除非最终指标是 RMSE，否则**不建议当主力** |
| **MAE** | 稳健但梯度为常数，收敛慢 | 若最终验收按 MAE，至少用它或与之对齐 |
| **Huber(δ)** | **尖峰处退化为线性、平坦处近 MSE，梯度平滑** | **推荐主力**：δ 取价格尺度中位绝对误差量级（如山东日前价 δ≈20~60 元/MWh），一把兼顾尖峰鲁棒与平滑收敛 |
| **分位数(pinball)** | 可产出各分位；τ=0.5 即 MAE | 用于概率输出或作为多样性成员 |
| **CRPS** | 评估完整分布；电力领域概率预测标准（与 Quantile Regression Averaging 组合为 GEFCom 系赢家打法） | 若未来要概率交付再上；做点预测时 CRPS≈多分位 pinball 平均 |

**核心原则（Lago 2021 §5.4 亦强调）**：**训练损失与最终评估指标对齐**。同时可训练「MAE head + Huber head」两个变体喂给 Ledger 融合，**用损失函数的多样性白赚集成增益**（成本仅是多跑一次）。

### 2.3 归一化 / 差分策略（季节性处理）

- **目标变换：asinh（arcsinh）方差稳定变换是电力价格预测的标准**（Uniejewski, Weron, Ziel, IEEE TPWRS 2018；Lago 2021 明确「因负价与尖峰，VST 已取代 log」）。它**同时处理负价与右偏尖峰**，且可逆（预测后 `sinh` 还原）。本项目 `iah_crps_loss.py` 已用 asinh/sinh（grep 到 `torch.asinh`/`torch.sinh`）——**确认对 TimeMixer/SGDFNet/RT916 的 point 输出也统一走这个变换，并注意 float64 中间量避免溢出**。
- **实例归一化（RevIN）/可逆归一化**：深度模型应对分布漂移的标准件（TSLib 系模型标配，Non-stationary Transformer 同源思想）。确认自研模型在输入段做 per-instance 归一化、输出段反归一化——**它对跨季节泛化常是几个百分点级收益**。
- **差分**：对统计/浅模型可做 `y_t - y_{t-24}`（或 96 口径 `y_t - y_{t-96}`）的季节差分降非平稳；对梯度模型一般 asinh + RevIN 已足够，差分反而增噪。

### 2.4 集成内部多样性（不新增模型结构的白赚精度）

- **多 seed + 多超参局部最优**：Lago 2021 实证 **DNN ensemble（4 次不同 seed/超参搜索的运行取算术平均）显著优于任何单模型**——原因正是「不同架构局部最优在验证集上几乎等好，平均后方差骤降」。本项目 GPU 模型按 3~5 个 seed 跑，几乎零额外工程成本。
- **多校准窗口**（Hubicka/Marcjasz/Weron 2018-19 系列，Lago 综述背书）：**几个短窗（8~12 周）+ 几个长窗（2~4 年）的算术平均**，显著优于任何单独窗口——短窗捕捉最新 regime，长窗稳季节性。特别契合本项目「账本每日找 30 个训练日」的既有设计：**把「短窗 + 长窗」的预测都送进 Ledger**。
- **多特征子集 / 多损失变体**：不同特征子集（如 ±天气组）、不同损失（MAE/Huber/分位数）成员各训一遍 → 多样性来源不花新架构。
- **集成规模上限**：**4~10 个成员**（Atiya 2020，引用于 Lago §5.12）——重尾分布下成员过多会引入离群预测反而变差。本项目 7 模型 + 若干变体正好落在甜区。
- **Ledger 融合的启示**：你的自适应权重已做了「按近期表现加权」；可补一个**朴素算术平均基线**做对照——若自适应权重长期赢不了算术平均，说明权重更新信号太弱（Lago 的 open-access 集成正是纯算术平均）。

## 3. 针对电力价格预测的特殊经验

### 3.1 价格尖峰 / 负电价

- **尖峰**：训练损失用 Huber/分位数而不是 MSE（见 2.2）；可对训练标签做 **winsorize（如 99% 分位截断）** 防单点主导，预测输出**不要**截断（否则尖峰段系统性低估）。Lago 综述指出：只截峰不还原会系统性低估尖峰段。
- **负电价**：**绝不 clamp 到 0**——负价是真实的供需信号（光伏正午过剩），模型应能输出负值；asinh 变换天然支持。评估负价漏判时**按事件数加权**（本 skill 已立规）。
- **尖峰分类器**：已有 ExtremPriceClf，是对的——文献里「分类尖峰事件 + 回归正常段」的两段式是主流打法之一，可继续作为**集成外挂**（尖峰日直接把分类器输出高权重）。

### 3.2 节假日前后的处理

- 电价在节假日、节前/节后窗口与平日**分布显著不同**（Weron 2014 要求测试期≥1年正是为覆盖节假日效应）。建议：
  - 日历特征加 **`is_holiday`、`days_to_holiday`、`days_after_holiday`**（中国：春节/国庆/五一及调休）；只给 `is_holiday` 二元 flag 往往不够，**节前 3 天 / 节后 3 天的梯度效应**要显式建模。
  - 训练时**不要硬删节假日样本**（样本本就少），而是让节假日 flag 参与；若个别节假日造成大幅误判，可在 Ledger 权重里给节假日日前后的预测降权或加校准。
  - 调休日（周末补班）在数据上表现为「周五上班+周日照常出清」——把**调休日历**并入 is_holiday 计算，这个细节在国内市场收益常被低估。

### 3.3 天气 / 新能源出力特征的价值

- **日前负荷预测 + 新能源（风电/光伏）出力预测是日前电价外生变量的头号信息源**（Lago 2021 benchmark 每市场仅用这两个外生量即支撑 SOTA 对比；山东省高渗透率下尤其成立）。
- 具体落地：
  - 已有 DB 里的 `fcast_*` 负荷/新能源组**直接作为外生特征**（注意只取**截止 14:00 / p56 可见**的日前预测，避免用到 target 日实际值造成泄漏——本 skill §4.2 已确认 cutoff=14）。
  - 温度→负荷的传导：加入温度特征（或其 HDD/CDD 展开）对高峰日（夏/冬）尖峰日特别有用；若拿到天气实况/预报，做成 `temp` + `temp_lag24` 即可。
  - **新能源渗透结构**：山东省正午光伏出力大 → 正午价格压制/负价频发。**显式加入「光伏出力预测 / 太阳辐照」比单加总负荷更能解释时段性价差**（可对比 96 点口径下正午时段 RMSE）。
  - 燃料/碳价：周频变量，一条日更列即可，对价格水平长程漂移有解释力。

## 4. 本项目最值得优先实施的 10 条（按投入产出比排序）

> 标「**加速**」= 直击 3 天回测瓶颈；「**精度**」= 直击最终指标；括号为预估收益（保守）。

1. **GPU 模型上 AMP 混合精度（autocast + GradScaler）** —— **加速**，RTX3090 是 Ampere、FP16 Tensor Core 峰值约 2 倍于 FP32，3 行代码白拿 **1.5~2×**，无精度损失（NVIDIA 官方 + PyTorch recipe）。注意：asinh/sinh、CRPS 等自定义损失在 fp32 段计算；维度凑 8 的倍数。回测 3 天 → 约 1.5~2 天。
2. **特征矩阵一次性离线预计算 + 7 模型共享 feature store** —— **加速**，砍掉 214 次循环里的重复滚动/滞后/聚合，通常省每期 30%~70% 前置耗时，还顺带保证 7 模型特征口径一致（防 24/96 混淆事故）。
3. **Warm-start 续训：加载前一日权重/优化器，大幅减少每期 epoch** —— **加速**，相邻日数据高度相关，续训可用极少数 epoch 收敛；与 AMP 叠加是「3 天→1 天」的两大支柱。务必守住「训练窗口不含 target 日」防泄漏。
4. **LR 调度的规范化：linear warmup + CosineAnnealing + 验证早停（安全阀）** —— **加速+精度**，固定 epoch 预算下收敛到更优极小；配合一次 LR Range Test 扫峰值 LR，比网格搜参省一个数量级算力（Leslie Smith 1cycle 同源）。
5. **Batch size 放大 2~4× + LR 按 sqrt/线性规则缩放** —— **加速**，喂饱 GPU、减少更新次数，验证集复验不降精度（Smith ICLR 2018）。
6. **损失对齐评估指标：主力换 Huber（δ≈中位绝对误差量级），保留 MAE head 送 Ledger** —— **精度**，尖峰价格下同时兼顾鲁棒与平滑收敛；用「损失函数变体」白赚集成多样性。
7. **集成多样性：GPU 模型 3~5 seeds ×（短窗 8~12 周 + 长窗 2~4 年）双窗成员，全送 Ledger** —— **精度**，Lago 实证 DNN 集成显著优于单模型；Hubicka/Marcjasz/Weron 实证双窗平均优于任何单窗。与 Ledger 现有 30 训练日设计天然衔接。
8. **确认并统一目标变换：asinh VST（point 输出也过 asinh/sinh）+ 深度模型 RevIN 实例归一化** —— **精度**，IEEE TPWRS 2018 标准做法；跨季节泛化通常是百分点级收益。96 点口径严格用 shift(96)/672，勿机械沿用 24 口径。
9. **TimesFM 固定预训练权重：零样本/只训轻量头，回测期避免全量微调** —— **加速**，基础模型在回测 214 天里全量微调是纯浪费；冻结主干做小 adapter/头即可拿到其泛化能力（Chronos/TSLib 系共识）。若精度允许，直接零样本评估。
10. **GPU 工程收尾件：`cudnn.benchmark` + `set_float32_matmul_precision('high')` + DataLoader `num_workers/persistent_workers/pin_memory` + 避免每步 `.item()`** —— **加速**，综合再省 10%~30%，全部零风险零精度损失。
