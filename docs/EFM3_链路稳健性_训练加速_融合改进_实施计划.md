## 设计原则（用户立规，贯穿所有修复）

### 原则 A：能运行是底线（P1 必须"有产出"）
一个公司要运行产品：**今天数据有问题，也一定要有一份预测文件**，公司才能结合上报。
- 任何环节失败 → 必须走到"至少一份可交付预测文件"
- 修复优先级 = 先保证"有输出"，再优化"输出的质量"
- P1 修复的核心不是"让它不报错"，而是"报错也一定有产物 + 明确标注"

### 原则 B：失败要"响亮"（静默 = 最危险）
日志/前端/数据库必须能呈现任何降级/回退/缺失：
- 每个降级都写 manifest + delivery_report 显式标注（原因/触发/数据覆盖）
- 报告/前端要有"告警段"，不只是 warning 埋在日志里
- 目标：运维一眼能判断"今天为什么是降级交付"

## Phase 1：链路稳健性修复（防"崩得不够响"，优先级最高）
> 目标：**任何失败都有产物 + 有明确标注**，杜绝静默污染与静默降级。

| 优先级 | 问题 | 修复 | 验收 |
|---|---|---|---|
| **P0** | 96点价格 null 时 `validate_daily_submission` KeyError 崩收尾（D1/E2） | `delivery_quality.py:499` 改用 resolution.slot_column；`_finalize_delivery` 的 postflight 包 try；**即使校验失败也走 fallback 产出文件** | 96点含 null 提交 → 明确报 null + 产出 fallback 文件，状态机完整 |
| **P0** | 96/24 数据粒度混用污染 actual 账本（D2，防患未然） | `_extract_actuals` 开头断言数据分辨率与 `--resolution` 匹配（分钟级唯一性），不匹配即报错不写账本 | 用错 data_path → 立即报错不写账本 |
| **P0** | 缓存校验不查 y_pred NaN，坏缓存静默通过（B1） | 缓存命中复用新预测的 NaN 检查；CSV 原子写（tmp+rename） | 半截坏文件被识别并触发重跑 |
| **P1** | predict 顶层 "error" 不被 ledger_full 识别（A1） | `ledger_full.py:105` 同时检查 failed/error 并提升 errors | error 时后续阶段跳过且 manifest 标注 |
| **P1** | scheduler 队列级异常静默丢结果（D3） | 队列异常补记每个未返回任务为 failed | manifest 无凭空消失的模型 |
| **P1** | 30 完整日不足硬 FAIL 无软降级（C1） | 加 `--min-training-days` 软门（如≥10天等权+显式标注，**仍产出预测文件**） | 账本不足期可交付但标注 degraded 原因 |
| **P2** | fallback 无分辨率校验、per-slot 覆盖不可见（E1） | 校验 hist 分辨率 + report 加 per-slot 覆盖统计 | fallback 报告可审计每槽数据来源 |
| **P2** | classifier 失败静默降级（D4） | 非 strict 也把 classifier 失败高亮进 delivery_report 告警段 | 报告显著提示"极端价未修正" |
| **P2** | 缓存无数据版本指纹（B2） | 缓存键加 data_path 哈希/修改时间 | 数据更新后未 --force 也能察觉 |
| **P3** | fallback 天不写账本导致连续失败雪崩（E3） | fallback 后提示/自动补跑 predict 补账本 | 连续失败期账本不恶化 |

**回归**：每修一项跑 4 件套 + 黄金基线 diff + `check_preflight_health.py` 全绿。

## Phase 2：训练加速（3天 → ~1天）
> 全部有权威实证；每项先在 1~2 天小规模 A/B 实测校准再全量。
> ⚠️ 确认：**AMP 混合精度项目已内置**（`optim/perf_knobs.py`：BF16 默认开 + GradScaler）→ 已达标，不重复。

| # | 措施 | 状态/预估收益 | 验证方式 |
|---|---|---|---|
| 1 | **AMP 混合精度** | ✅ **已内置**（perf_knobs.py，BF16+Scaler） | 已达标 |
| 2 | **特征矩阵离线预计算 + 7模型共享 feature store** | ⭐ 每期省30~70%前置；**设计重点：零精度损失**（特征值逐位一致，仅缓存计算） | 214天回测前置耗时对比 + 特征逐位 diff |
| 3 | **Warm-start 续训**（加载前一日权重，少 epoch 续训） | ⭐ 与特征预计算叠加压到1天；省下的时间可增加每期 epoch 让模型更充分收敛 | 防泄漏验证：训练窗不含target日；精度不降 |
| 4 | **LR 规范化**：linear warmup + CosineAnnealing + 验证早停 | 收敛更快更稳 | 一次 LR Range Test 扫峰值LR |
| 5 | **Batch size 放大 2~4× + LR 缩放** | 减少更新次数 | 验证集复验不降精度 |
| 6 | **TimesFM 冻结主干**（只训轻量头/零样本） | 免全量微调浪费 | 精度不降则采纳 |
| 7 | **GPU 工程收尾**：cudnn.benchmark/TF32/DataLoader参数 | 综合10~30% | 零风险零精度损失 |

### 2.1 特征预计算设计要点（#2，用户重点关注"不失精度"）
- **只缓存，不改变特征值**：把 214 天回测需要的全部特征（滞后/滚动/日历/外生）一次算好存 parquet；
  7 模型从同一 feature store 按日期切片，**逐位值与现在重算完全一致**（黄金基线 diff 保证）
- **防泄漏不变**：预计算也遵守 cutoff=14 规则；target 日特征不含未来信息
- **口径统一**：顺带消灭 24/96 shift 混淆隐患（skill §2 红线）
- **验收**：预计算前后某日特征矩阵 `assert_frame_equal` 全等 → 精度零损失

### 2.2 Warm-start 续训设计要点（#3）
- **原理**：相邻日数据高度相关 → 加载前一日权重/优化器状态，以极少数 epoch 续训收敛
- **时间再分配**：省下的墙钟可 → 提高每期 epoch 上限/更长序列/更充分收敛 → **精度只升不降**
- **防泄漏铁律**：训练窗口仍只到 target 日前一天，续训只是"初始点=前一日权重"（skill §4.2）
- **验收**：warm-start 与冷启动同精度下 epoch 减少 ≥50%；或同预算下精度提升

**验收**：214 天回测墙钟压到 ~1 天；单日 NORMAL 交付不变；指标不劣化（只升不降）。

## Phase 3：预测精度 + 融合改进
> 目标：三个臭皮匠顶个诸葛亮——融合更强，极端价处理更准。

### 3.1 模型侧（Phase 2 顺带）
- 损失对齐：主力换 **Huber(δ≈20~60 元/MWh)**，保留 MAE head 送融合（多样性白赚）
- 目标变换：确认 **asinh VST** 统一（含 point 输出）+ 深度模型 **RevIN**
- 特征：加 **节假日+节前/节后3天 flag、调休**、光伏/风电出力预测外生（注意 p56 截止防泄漏）
- 集成多样性：GPU 模型 **3~5 seed ×（短窗8-12周 + 长窗2-4年）** 成员送 Ledger

### 3.2 融合侧（在现有 BGEW 上补强，不推翻）
| # | 改进 | 说明 |
|---|---|---|
| 1 | **OOF 融合回验守卫** | 滚动OOF评估 融合 vs 等权 vs 单模型最优；赢不了等权就回退+告警 |
| 2 | **事件加权损失进权重** | SMAPE-floor50 抹掉负价技能 → 事件级表现单独计分进 BGEW |
| 3 | **极端价修正改造**（见 3.2b 专项） | 根因不是位置是门控量；推荐"软修正+置信度兜底" |
| 4 | **96点逐小时块权重** | 三段 → 每小时块（24块/天），时段特异性更强 |
| 5 | **朴素平均基线对照** | 交付报告永远带等权融合列，BGEW 长期不赢则警示 |
| 6 | **融合诊断面板** | 可视化权重轨迹/贡献率/累计赢率 |

### 3.2b 极端价修正专项（基于 `docs/极端电价修正_前置vs后置_调研报告.md`）
**结论：根因不是"前置/后置"，而是后置门控用了被均化污染的 `y_fused`。**

- **现状缺陷**：`classifier_bridge.py:90-92` 用 `final_pred==1 ∧ y_fused≤100 → -80`。多数模型漏报时
  融合均值被拉高 >100 → 真负价被门槛挡掉（数学：平方损失模型对罕见极值系统性回归到均值，同号误差不可分散）。
- **数学恒等式**：共享修正函数 h(p) 时，前置软修正 ≡ 后置软修正；前置真正价值在"per-model 差异强度"。
- **推荐（混合）**：`y_final = y_fused + h(p)·(−80−y_fused)`，去掉 `y_fused≤100` 门槛；
  分级软修正（p_lo≈0.25/p_hi≈0.80），高置信 p≥p_hi 直接触底；可选一致性门 `p≥θ ∧ min_m ŷ_m≤30`。
- **实现策略**：先做等价后置软修正（一行改动，`classifier_bridge.py`），A/B 后再决定是否上 per-model 差异化强度。
- **实验**：V0(现状)/V1(硬前置)/V2(软修正)/V3(混合) 对照，事件级指标（漏报 M1/召回 M2/误报 M4）+ DM 检验。

### 3.3 验收
- 融合守卫触发回退时 manifest/report 明确标注
- 负价/尖峰事件级指标提升（按事件数加权，skill 红线；M1=真事件被门槛挡住的比率→0）
- 96点聚合到24点与24点腿同口径对比不劣化

## 风险与纪律
- **能运行是底线**：任何失败都要有产物 + 明确标注（设计原则 A）
- **绝不静默**：任何降级/回退/缺失都要在 manifest + report 显式标注（设计原则 B）
- **每步验证**：改一处测一处，A/B 对照，不批量盲跑（HCH-v2 T0/T1 纪律同源）
- **数据真实**：96点 actual≠fcast、cutoff p56、24/96 不混用（skill §1/§2/§4.2）
- **成本控制**：GPU 重活只在服务器，本机 CPU-only 不做会误导的判断
- **优先级**：Phase 1 链路稳健性 > Phase 2 加速 > Phase 3 精度融合（先确保不崩、再求快、最后求准）
