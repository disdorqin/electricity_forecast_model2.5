# 信息可得性自动化门控设计

> status: active
> 日期：2026-08-16
> 阶段：设计，尚未接入全部模型特征工程

## 目标

把“不能使用目标日实际值”和“实时只能看到14:00以前数据”从人工审计规则，升级为可执行、可阻断、可追溯的运行时契约。

## 推荐架构

### 1. ForecastContext

所有生产模型统一接收：

```text
target_day
task
resolution
decision_ts
cutoff_ts
last_visible_period
target_columns
```

`cutoff_ts`只在CLI入口计算一次，下游不再自行计算14:00、15:00或`end_dt - 10h`。

### 2. FeatureRegistry

每个特征注册以下元数据：

```text
name
source_table
role: forecast | actual | target | lag
available_at
allowed_tasks
required_shift_slots
```

例子：

```text
fcast_wind:          role=forecast, allowed_tasks=[dayahead,realtime]
actual_wind:         role=actual,   required_shift_slots>=1 day
rt_cq_price:         role=target,   target_day direct use=forbidden
da_cq_price:         role=target,   DA target or approved RT anchor
```

### 3. AvailabilityAudit

模型进入推理前执行只读审计：

1. 检查目标日`actual_*`是否非空并被特征使用；
2. 检查RT特征在`ds > cutoff_ts`是否仍携带真实值；
3. 检查`data_cutoff <= cutoff_ts`；
4. 检查lag列是否经过与分辨率匹配的shift；
5. 检查输入分辨率、business_day、slot列是否一致；
6. 输出特征指纹和审计结果。

## 阻断策略

| 级别 | 条件 | 行为 |
|---|---|---|
| P0 | target-day actual/RT truth直接进入特征 | 阻断模型，不写入预测账本 |
| P1 | cutoff后数据未遮蔽、来源不明 | 阻断RT模型，写入manifest和报告 |
| P2 | 特征缺失、降级填充、非生产来源 | 允许fallback，但必须显式告警 |

每次运行写入：

```text
run_manifest.json
model_availability_audit.json
delivery_report.md
```

## 分阶段落地

1. **Phase 1：** 先实现`ForecastContext`和统一cutoff计算。
2. **Phase 2：** 给共享数据适配器增加FeatureRegistry和静态字段审计。
3. **Phase 3：** 在TimesFM、SGDFNet、TimeMixer、RT916逐个接入运行时断言。
4. **Phase 4：** 将审计结果接入CI，使用构造数据验证p56/p57边界。

不建议一次性重写所有模型内部特征工程；先把入口和共享数据层封闭，再逐模型迁移，风险最低。
