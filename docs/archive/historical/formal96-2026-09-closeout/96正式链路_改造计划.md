## 1. 最终目标：只保留一条干净的正式生产链路

公司/前端最终只需要三个入口：

```powershell
python main.py --96 2026-08-16
python main.py --96 2026-08-16 --predict both
python main.py --96 2026-08-16 --finish
```

旧 `--pipeline ...` 接口保留为 internal/advanced compatibility，不作为生产用户入口。

### 1.1 正式完整链路

```text
正式 96 点输入
    ↓
DB sync + immutable D/T snapshot + FeatureViewBuilder
    ↓
┌──────────────────────── 模型预测阶段 ────────────────────────┐
│ CPU process（max_cpu_workers=2, DAG-aware）                  │
│   TimesFM DA ─────→ TimesFM RT                              │
│   SGDFNet anchor prepare ─→ SGDFNet RT                      │
│   LightGBM DA                                                │
│                                                              │
│ GPU process（max_gpu_workers=1, 严格串行）                  │
│   TimeMixer DA ─→ TimeMixer RT ─→ RT916 joint(DA→RT)        │
└──────────────────────────────────────────────────────────────┘
    ↓
prediction / actual ledger
    ↓
smape_reg / SLSQP 权重学习
最近30个完整历史日，96点三段
    ↓
DA / RT weighted fuse
    ↓
final outputs
    ↓
submission_ready.csv
    ↓
postflight / manifest / exit code
```

**ExtremePriceClf 不属于新的正式主链。**  
它保留源码、历史 replay、cache 和独立 shadow/experiment 能力，后续优化通过独立晋升后才允许重新进入生产。

### 1.2 正式模型池唯一来源

只允许 `fusion/model_pool.py` 声明生产模型池：

- DA：`lightgbm, timesfm, timemixer`
- RT：`timesfm, sgdfnet, timemixer, rt916`

其他模块只能读取该定义，不得重复声明另一份“生产模型列表”。

SGDFNet anchor prepare 和 RT916 内部 DA 是模型内部节点，不加入 DA 融合池。

## 3. 已冻结业务与工程契约

### 3.1 SGDFNet

今天预测明天 D：

```text
SGDFNet da_anchor = 今天（D-1）的完整日前 96 点
D-1 p1...p96 → D p1...p96
```

禁止使用 target D 当天日前作为 anchor。

historical same-hour median 只能是异常 fallback，不得成为正常生产输入。

### 3.2 CPU/GPU

- CPU process 和 GPU process 必须同时启动；
- GPU 单卡严格串行；
- CPU 正式目标 `max_cpu_workers=2`；
- CPU 必须 DAG-aware，dependency ready 后才 submit；
- 不能简单把当前 serial worker 数从1改成2；
- dependency failure 只阻断真正依赖节点，独立模型继续运行。

### 3.3 task identity

调度节点使用：

`(model_name, task/internal_node)`

禁止继续用模型名并集筛选 task。

必须保证：
- `--predict dayahead` 只产 DA 3 模型；
- `--predict realtime` 只产 RT 4 模型及其明确的内部前置节点；
- `--predict both` 执行完整预测 DAG。

### 3.4 权重学习器

用户已确认正式默认继续使用当前 Git 最新的：

`smape_reg / SLSQP`

NNLS、BGEW、champion_short 只作为 internal/experiment 显式选项。

### 3.5 RT916 正式训练 stride

用户已正式裁决：

`RT916_TRAIN_STEPS = 24`

含义是训练样本滑窗 stride=24，而不是 epoch/gradient steps。96点下约每6小时生成一个训练窗口。已有历史实测已经证明 24 相比 1 大幅提速，同时明显优于 stride=96 的精度退化，因此本轮**不再做 stride sweep**。

正式 façade 必须内部显式设置/传递 production stride=24，并写入 manifest；不得要求部署人员手工设置环境变量。

### 3.6 全局“代码-测试-文档原子同步”硬门

该规则适用于本规范中的**每一个代码修改 Phase**，不是只针对 classifier：

1. 先按代码关联图完成最小必要修改；
2. 运行该 Phase 对应的最小测试；
3. 测试 PASS 后，立即检查并更新所有受影响的权威文档、README、RUNBOOK、OUTPUT_CONVENTION、PROJECT_LAYOUT、代码 docstring/comment、示例命令和 manifest 字段说明；
4. 再运行文档/CLI/契约相关回归；
5. 只有“代码 + 最小测试 + 文档同步 + 契约回归”全部完成，Phase 才能标记 PASS。

禁止出现：代码已经改变但文档留待以后补、README 与实际默认不一致、测试仍按旧阶段数/旧输出名运行。

## 4. 当前主要问题

### P0-1：split_process CPU 子进程仍被写死串行

现状：`_split_queue_entry()` 内部实际 `max_cpu_workers=1`。

问题：没有利用服务器多核 CPU。

目标：DAG-aware `max_cpu_workers=2`。

### P0-2：旧多 worker 队列不是 DAG-aware

现状：旧 `_run_queue(max_workers>1)` 一次性 submit 所有 task。

风险：TimesFM RT 可能在 TimesFM DA 文件尚未完成时启动并失败。

目标：ready queue / topological execution。

### P0-3：unified plan 用模型名并集筛 task

现状：相同模型名同时存在 DA/RT 时会误带 task。

目标：以 task-node identity 精确选择。

### P0-4：SGDFNet anchor contract 错

现状：当前行 `日前电价` → target-day mask 后走历史 median fallback。

目标：D-1 DA 96点按 p1..p96 映射到 D。

### P0-5：production ledger 尚未冷启动

当前 `outputs/96/ledger` 不具备 30 个完整历史日，直接上线会在 weight 阶段失败。

目标：在正式一键链路验收前完成 production ledger bootstrap。

### P1-1：ExtremePriceClf 仍硬接生产链

已决定软下线。

目标：生产 `fuse → final`；classifier 留 shadow。

### P1-2：RT916 正式 stride 已冻结为24，但代码入口尚未生产化

用户已裁决 production stride=24。当前问题不再是“选多少”，而是现代码仍通过 `RT916_TRAIN_STEPS` 环境变量兼容入口读取，正式 `--96` 还没有把24固化成生产配置并写入 manifest。

目标：正式 façade/adapter 显式使用24；旧 internal CLI 可保留环境变量覆盖用于实验，但 production façade 不受外部环境污染。

### P1-3：文档历史错杂

已经发现：
- 代码默认 smape_reg，旧 README/RUNBOOK 曾写 NNLS；
- classifier 行为、五阶段描述分散在多份文档；
- split_process 文档仍称“候选”。

目标：每个生产行为变更必须代码+测试+所有权威文档同一变更完成。

## 5. 实施 Phase A：先修预测 DAG，不改模型数学逻辑

### A1. 建代码关联图

执行 AI 开始前必须明确：

`main/parser → ledger_predict → ResourceScheduler → adapters → prediction files → ledger`

不得只看 `resource_scheduler.py` 单文件。

### A2. 重建 CPU ready-queue

目标：

```text
worker 1/2：
TimesFM DA → TimesFM RT

另一 worker 可并行：
SGDFNet anchor prepare → SGDFNet RT
LightGBM DA
```

具体谁占 worker 不硬编码线程号，由 ready queue 调度。

### A3. GPU 保持严格串行

```text
TimeMixer DA → TimeMixer RT → RT916 joint DA→RT
```

不允许同卡多个训练模型并发。

### A4. 修 dependency

保留：
- TimesFM RT ← TimesFM DA
- TimeMixer RT ← TimeMixer DA
- SGDFNet RT ← SGDFNet anchor prepare

删除错误 dependency：
- SGDFNet RT ← TimesFM DA
- RT916 RT ← TimeMixer RT

RT916 依赖只在自身 joint DA→RT 内部。

### A5. 最小测试

不先跑重模型，先做：
1. DAG ready queue 单元测试；
2. CPU/GPU child 同时启动 smoke；
3. dependency ready-before-start 测试；
4. parent failure only blocks child 测试；
5. independent task survives sibling failure；
6. `target=dayahead/realtime/both` 精确 task 集合测试。

通过后再跑一日模型级 smoke。

## 7. 实施 Phase C：固化 RT916 production stride=24

该值已经由用户正式裁决，本轮不再调参。

### C1. 当前证据

RTX4060、三个月窗历史实测：

| stride | 训练样本量级 | 时间 | 记录的精度现象 |
|---:|---:|---:|---|
| 1 | ~11393/段 | ~1000s+ | 基准，太慢 |
| **24** | 404/段 | **~98s** | SMAPE约0.23~0.32，可接受 |
| 96 | 102/段 | ~70s | SMAPE约0.45~0.82，明显退化 |

### C2. 正式修改

- production `--96` façade 强制 production stride=24；
- RT916 adapter/manifest 显式记录 `train_stride=24`；
- 不依赖部署 shell 中的 `RT916_TRAIN_STEPS`；
- internal/experiment 入口可继续允许显式环境变量覆盖，但必须与 production façade 隔离；
- 若环境里存在其他值，正式 façade 应覆盖为24或 fail-fast，不能静默污染生产。

### C3. 最小测试

1. production façade 未设环境变量 → RT916 实际 stride=24；
2. 外部环境设成1/96 → production façade 仍为24；
3. internal/experiment 入口仍可显式 override；
4. manifest 明确记录24；
5. RT916 单模型 smoke 能读取该配置并产生完整96点结果。

测试 PASS 后同步：README、RUNBOOK、RT916 代码注释、正式 CLI 参数说明、manifest/output contract。
