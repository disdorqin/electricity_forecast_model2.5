## 1. 阶段目标

M1 不追求“立刻把目录看起来清爽”，而是先保证以后不会继续变乱：

1. `python main.py --96 DATE` 只能写入明确的 production-owned 路径；
2. 项目根目录不再产生模型日志、pytest 临时目录、Agent 验收日志和一次性 probe；
3. 模型内部 scratch 由外层 runner 注入，模型不得自行决定项目根输出；
4. formal96 runtime 改为一次 invocation 一个 sandbox，成功整体清理，异常可诊断并由 TTL 回收；
5. crawler、科研实验、打包构建、正式预测四种资产彻底分域；
6. 不改变当前 DA3/RT4、T-2 learner、warm-start ledger、split_process、四阶段 final 链。

**M1 只止血；历史目录迁移/删除属于 Phase M2。**

## 4. 根因分类

### 4.1 明确属于链路/代码输出设计问题

#### A. LightGBM 根日志

`lightGBM/infer_da_fix.py` 原先直接打开项目根 `../lgbm_predict_diag.log`。2026-09-19 已改为模块标准 `logging`，formal 调用由 `ledger_predict` 的 file handler 收敛到 `runs/D/logs/pipeline.log`；预测数学未改。standalone `__main__` 的示例 CSV 不在 formal 调用图，本轮不扩大处理。

#### B. formal96 runtime 不是 attempt-scoped

已核验根因并于2026-09-19完成修复：`pipelines/ledger_predict.py` 不再为 formal96 硬编码 canonical runtime，而是从已解析的 `runs_root` 推导 sibling runtime：`runtime_root = runs_root.parent / "runtime"`。默认仍是 `outputs/96/runtime`；测试/甲方若指定 `.../isolated/runs`，scratch 自动进入 `.../isolated/runtime`。24/legacy profile 保持既有行为，不新增用户 CLI 参数。

目标结构:

```text
outputs/96/runtime/
  attempt_<target>_<attempt_id>/
    asof/input.parquet
    models/
      lightgbm/
      timesfm/
      timemixer/
      sgdfnet/
      rt916/
    temp/
    attempt.json
```

已实现口径：
- 一个 formal96 invocation 一个 `attempt_<target>_<attempt_id>/`；
- as-of 固定为 `attempt/asof/input.parquet`，五模型 scratch 在 `attempt/models/`；
- direct `--predict` 成功后删除整个 attempt；完整 `--96` 中 prediction 子阶段先删 model scratch、父链在 NORMAL 后删整个 attempt；
- controlled failure 保留单一 attempt 给诊断，24h TTL maintenance 可回收；
- attempt_id 隔离并发调用；bootstrap staging 不与 prediction attempt 共目录。

#### C. crawler source / frozen runtime 原先职责混杂（已修）

实盘复核后确认，根 `output_96/` **不是 shell CWD 随机泄漏**。旧代码明确规定：源码运行时 `BASE_DIR=项目根`，因此主动写 `项目根/output_96`；PyInstaller frozen 运行时 `BASE_DIR=exe目录`，因此写 `dist/crawler/output_96`。两者都不受 shell CWD 影响，但源码运行污染项目根，不利于长期维护。

2026-09-19 已最小修复：
- frozen EXE 行为不变：仍写 `<exe目录>/output_96/`；
- source-mode 固定改写 `<项目根>/outputs/crawl/runtime_96/`；
- 根历史 `output_96/` 已迁入 `outputs/archive/diagnostics_history/crawler_source_root_output_96_pre_20260919/`；
- `dist/crawler/config.example.json` 中无效的 `output_dir` 字段已移除，避免误导；
- crawler runtime tests 18/18 PASS；
- 当前生产 `crawl_96_auto_v6.exe` 未重打包、未覆盖，保持原二进制不变。
